# ADR-002: RabbitMQ en lugar de Kafka, e idempotencia en PostgreSQL

- **Tipo:** Tecnológica
- **Estatus:** Aceptado

## Contexto
Se requiere mensajería para notificaciones y conciliación y evitar cobros duplicados.

## Decisión
Usar RabbitMQ para colas de trabajo y una columna idempotency_key con restricción UNIQUE.

## Justificación
El volumen de una cooperativa no requiere un log distribuido como Kafka; RabbitMQ ofrece reintentos y DLQ de forma sencilla.

## Consecuencias
Menor capacidad de reprocesar historial masivo que con Kafka.
